# Download Organizer

Windows 10/11 다운로드 폴더의 파일을 미리 분석하고, **최종 확인 후** 날짜별 이동 및 중복 격리를 수행하는 Tkinter/ttk 앱입니다. Python 3.12를 사용합니다.

## 실행 및 배포

클라우드 개발환경에서 다음 명령을 사용합니다. Python에 Tcl/Tk가 포함되어 있어야 합니다.

```powershell
python -m pip install -e ".[dev]"
python -m download_organizer
python -m pytest -v
```

GitHub Actions의 `Windows tests and EXE`는 Python 3.12 테스트와 PyInstaller 빌드 후 `DownloadOrganizer-Windows` 아티팩트를 제공합니다. 아티팩트를 내려받아 압축을 풀고 `DownloadOrganizer.exe`를 실행합니다. PC 로컬 개발환경은 필요하지 않습니다. EXE는 아직 코드 서명되지 않았습니다.

```powershell
python -m PyInstaller --noconfirm --clean --onefile --windowed --name DownloadOrganizer --paths src src/download_organizer/launcher.py
```

Windows EXE는 Windows 러너에서 빌드합니다. 긴 경로는 Windows의 긴 경로 지원 설정과 파일시스템 제한을 따릅니다. 경로 오류는 건너뛰고 표시합니다.

## 사용 순서

1. Windows Known Folder API로 다운로드 폴더를 기본 선택합니다. 실패하면 홈의 `Downloads`를 사용합니다. 다른 폴더도 선택할 수 있습니다.
2. 기본 날짜 기준은 **Windows 생성일**이며 수정일도 선택할 수 있습니다. 날짜는 PC 로컬 시간 기준 `YY.MM.DD`입니다.
3. **읽기 전용 분석**을 누릅니다. 메타데이터 수집과 중복 검사는 백그라운드에서 실행합니다. 미리보기에서는 폴더 생성·이동·삭제를 하지 않습니다.
4. 목록에서 원본/예상 경로, 날짜, 용량, 처리 여부, 중복 보존/격리 여부 및 경고를 확인합니다. 여러 행을 선택하고 **처리 여부 전환**으로 개별 대상을 제외할 수 있습니다.
5. 중복 그룹의 파일 한 개를 선택해 **중복 보존본으로** 버튼을 누르면 보존 대상을 바꿀 수 있습니다. 보존본을 처리 대상에서 제외해도 원래 위치에서 보존되고 다른 중복본의 격리 전 검증에 사용됩니다.
6. **선택 파일 정리…**에서 실제 처리 개수, 날짜 이동 목적지, 격리 개수/경로 및 중복 예상 용량을 확인합니다. 확인 창의 기본 선택은 취소입니다. 취소 시 어떤 파일이나 폴더도 변경하지 않습니다.
7. 실행하면 기존 날짜 폴더를 재사용하거나 새로 생성합니다. 대상 이름이 있으면 덮어쓰지 않고 건너뜁니다. 완료 또는 부분 취소 후 다시 분석해야 합니다.

중복 예상 용량은 선택한 중복본 크기의 합계입니다. **격리는 영구 삭제가 아니므로 같은 디스크의 여유 공간은 늘어나지 않습니다.** 실제 정리는 중간 취소 시 이미 완료된 파일까지 되돌리지는 않습니다.

## 중복 판정

- 직계 일반 파일 중 크기가 같은 파일만 SHA-256 대상으로 선정합니다.
- 전체 파일을 1 MiB 청크 단위로 읽고, 같은 해시도 추가 바이트 비교로 확인합니다.
- 동일 내용에서는 생성일이 가장 빠른 파일을 기본 보존합니다. 생성일이 제공되지 않는 플랫폼에서는 수정일을 사용하고, 같으면 경로 순으로 결정합니다.
- 생성일을 제공하지 않는 Unix 환경에서 생성일 기준 분석은 오류로 안내합니다. Unix ctime을 생성일로 사용하지 않습니다.
- 큰 파일의 내용 전체를 메모리에 적재하지 않습니다. 파일 목록과 미리보기 메타데이터는 메모리에 보관합니다.

## 보호 정책과 격리

- 현재 사용자 홈 **아래의 개별 폴더**만 정리합니다. 홈 자체, 다른 사용자 폴더, 시스템 폴더, AppData 및 주요 설정 폴더를 제외합니다. 사용자 홈 밖의 별도 드라이브 다운로드 폴더도 현재는 차단합니다.
- 선택 폴더의 직계 파일만 분석합니다. 하위 폴더, 심볼릭 링크, Windows junction/reparse point 및 날짜 폴더 내부는 제외합니다.
- `.crdownload`, `.part`, `.partial`, `.download`, `.tmp`, `.temp`, `~$` 임시 파일과 읽기 불가능 파일을 제외합니다. 일반 확장자의 다운로드 상태를 확장자만으로 완전히 감지하지는 못합니다. Windows에서는 쓰기 핸들과 충돌하는 파일을 실행 시 건너뜁니다.
- Windows 실제 작업은 쓰기·삭제 공유를 금지하는 원본/보존본 핸들을 유지합니다. 파일 크기·수정 시각·파일 식별 정보와 내용 해시를 재검증합니다. Linux 테스트 구현은 메타데이터·해시 재검증을 사용하며 Windows 공유 잠금과 동일한 보장을 제공하지 않습니다.
- 대상은 배타적 생성(`xb`)으로 기록하고 복사 완료/대상 해시 검증 후 원본을 제거하여 이동합니다. 원본 변경이나 복사 실패 시 원본을 유지하고 생성한 부분 복사본을 정리합니다. 수정 시각은 유지하지만 Windows 생성 시각과 ACL 등 전체 메타데이터 보존은 아직 지원하지 않습니다.
- 중복본은 `%LOCALAPPDATA%/DownloadOrganizer/Quarantine/<고유ID>/files/<파일명>`에 격리합니다. Windows 외 기본 위치는 `~/.local/share/DownloadOrganizer/Quarantine`입니다.
- 각 고유ID 폴더의 `original.json`에 원본 경로·격리 경로·SHA-256을 **이동 전** 기록하고 디스크에 반영합니다. 실패/중단 시 기록만 남을 수 있으므로 복원 전 실제 격리 파일 존재를 확인해야 합니다. 자동 복원·보관 기간 만료 삭제 기능은 없습니다.
- 프로세스 강제 종료/전원 차단 시 복사본과 원본이 함께 남을 수 있습니다. 악의적 외부 프로세스의 디렉터리 교체까지 방어하는 보안 경계나 전체 작업 트랜잭션은 아닙니다. 작업 중 폴더를 다른 도구로 변경하지 마세요.

## 프로젝트 구조

```text
src/download_organizer/
  analyzer.py      # 읽기 전용 메타데이터·날짜 예상 경로·스냅샷
  organizer.py     # 중복 검증·미리보기·선택·안전 작업·격리 기록
  gui.py           # Tk GUI, 작업 스레드·큐, 보존본 변경·최종 확인
  paths.py         # Windows Known Folder 경로
  __main__.py      # python -m 진입점
  launcher.py      # PyInstaller 진입점
  __init__.py      # 패키지 선언
tests/
  test_analyzer.py # 읽기 전용 분석 테스트
  test_organizer.py # 임시 폴더 기반 중복·이동·격리·변경 보호 테스트
  test_gui.py      # GUI 분석·오류 복구·최종 확인 취소 테스트
.github/workflows/windows.yml # Windows 테스트·EXE 빌드·아티팩트 배포
pyproject.toml
```

테스트는 임시 디렉터리만 사용합니다. 디스플레이가 없는 Linux에서는 GUI 통합 테스트가 skip되며 Windows CI에서 실행합니다. Windows 링크 권한이 없으면 해당 링크 테스트가 skip됩니다.
